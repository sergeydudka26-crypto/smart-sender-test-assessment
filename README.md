## Запуск тестів

Для автоматизованого тестування використовується **Vitest** разом із **MSW**.

Запуск тестів:

```bash
npx vitest
```

Тест перевіряє коректність роботи механізму `rotate` при виникненні паралельних 401 помилок.

## Основні технічні рішення

1.  **Архітектура API**:
    - Реалізовано `ApiClient` як централізовану точку взаємодії, що інкапсулює логіку заголовків (CSRF, X-Requested-With) та стратегію повторних запитів (retry logic).
2.  **Керування сесією**:
    - `device_session_token` зберігається лише в пам'яті (`in-memory`).
    - Для стабільності сесії використано `AuthContext`.
3.  **Обробка конкурентності (Race Conditions)**:
    - Впроваджено патерн "Promise Deduplication" для `rotate`-запиту. Якщо кілька запитів отримують 401 одночасно, вони очікують завершення одного спільного `rotate`-запиту.
4.  **Безпека та Fingerprint**:
    - Генерація стабільного 32-символьного ID пристрою, який зберігається в `localStorage` один раз і передається в auth-запитах для ідентифікації сесії.
5.  **Робота з URL**:
    - Стан пагінації та пошуку синхронізовано з параметрами запиту (query params) через `useSearchParams`. Це забезпечує коректну роботу навігації (кнопки «Назад/Вперед») та відновлення стану сторінки після оновлення. Для підтримки чистоти URL параметр `page` автоматично видаляється, якщо вибрано першу сторінку.

## Що залишилося нереалізованим

- **419 Token Mismatch Handling:** У методі `ApiClient.request` не реалізовано автоматичне повторне отримання CSRF-токену при отриманні помилки 419 (це було вказано як "перевага", а не обов'язкова вимога).
